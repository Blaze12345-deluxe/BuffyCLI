================================================================================
                              GLOSSARY
================================================================================

This file defines the key terms and concepts used throughout the Buffy
project documentation and source code.

A

Alias:
  A shortcut that maps one command name to another. Defined in
  ~/.buffy/aliases.json. For example, "ve" -> "pip-env" means "buffy ve"
  executes the same as "buffy pip-env".

AST (Abstract Syntax Tree):
  A tree representation of a parsed BSL script. The parser produces an AST
  from tokens, and the interpreter walks the AST to execute instructions.

B

BSL (Buffy Script Language):
  The simple scripting language used to write Buffy commands. A declarative,
  line-oriented language with instructions like WRITE, RUN, WAIT, CLEAR,
  EXIT. File extension: .bsl.

BuffyError:
  The top-level error type used by CLI dispatch and package management.
  Defined in src/error.rs using thiserror.

Buffy Home:
  The ~/.buffy/ directory where all Buffy data is stored: configuration
  files, installed packages, cache, and logs.

C

Cache:
  A local copy of repository indexes stored at ~/.buffy/cache/indexes/.
  Used to avoid redundant network requests. Cleared with "buffy --clean"
  or "buffy --repo refresh".

CLI (Command-Line Interface):
  The command-line interface to Buffy. Accepts flags (--install, --list,
  etc.) and BSL commands.

Commands Directory:
  ~/.buffy/commands/ where installed .bsl files are stored. Each package
  gets its own subdirectory.

Conflict Preference:
  A stored user choice for which version of a package to prefer when
  multiple packages share the same name. Stored in aliases.json.

D

Dependencies:
  System dependencies: external tools required by a package (e.g., python3,
  docker). Checked on $PATH.
  BSL dependencies: other Buffy packages required by a package. Auto-
  installed during package installation.

Discover:
  The feature that scans $PATH for development tools and suggests matching
  packages from configured repositories.

Doctor:
  The full system diagnostics command ("buffy --doctor"). Runs 11 checks
  to verify system health.

E

Executor:
  The BSL subsystem that spawns shell processes and executes RUN commands.
  Detects the user's shell from the SHELL environment variable.

F

Flat Lookup:
  A resolver fallback that scans all package subdirectories for a .bsl file
  matching the command name. Allows "buffy cd-down" instead of "buffy
  file-system cd-down".

I

Index:
  A JSON file (index.json) at the root of each package repository listing
  all available packages with their metadata, versions, and dependencies.

Installed Packages:
  Packages that have been downloaded, verified, and copied to
  ~/.buffy/commands/. Tracked in installed.json.

Interpreter:
  The BSL subsystem that walks an AST and executes each instruction
  sequentially. Handles WRITE, RUN, WAIT, CLEAR, EXIT, and OUTPUT toggle.

L

Lexer:
  The BSL subsystem that converts raw source text into tokens (identifiers,
  string literals, numbers, etc.) with line numbers.

Linter:
  The diagnostic subsystem that analyzes BSL scripts for issues: missing
  metadata, empty instructions, destructive commands, etc.

M

Manifest:
  The package.json file containing a package's metadata (name, version,
  author, sha256, dependencies, tags).

Metadata:
  The section at the top of a .bsl file containing VERSION, AUTHOR,
  DESCRIPTION, and OUTPUT settings. Must appear before any instructions.

O

OUTPUT:
  A metadata setting and runtime toggle that controls whether RUN command
  output is shown to the user (true) or hidden (false).

P

Package:
  A collection of one or more .bsl files distributed together with a
  package.json manifest and SHA-256 checksum.

Parser:
  The BSL subsystem that converts tokens into an AST with validation.

Plugin:
  Another name for a package. A group of BSL scripts distributed through a
  GitHub repository.

R

Repository:
  A GitHub repository containing a collection of packages with an index.json
  at its root.

Resolver:
  The subsystem that matches CLI arguments to .bsl files by walking the
  ~/.buffy/commands/ directory tree.

S

SHA-256:
  The hash algorithm used for package integrity verification. Each .bsl file
  has its own SHA-256 hash stored in both package.json and {name}-SHA.txt.

Shell Completion:
  Tab-completion for CLI flags generated by clap_complete. Supports bash,
  zsh, fish, elvish, and powershell.

T

Token:
  The smallest unit of BSL syntax after lexing. Types include Ident,
  StringLit, Number, Equals, Newline, and Eof.

V

Variable:
  A placeholder in a .bsl file that is expanded before execution. Built-in
  variables: ${HOME}, ${USER}, ${PWD}, ${TEMP}, ${DATE}, ${TIME}.
  Positional arguments: ${1}, ${2}, ..., ${N}.

Version:
  Date-based version format YYYY.MM.DD. A build number can be appended
  for multiple same-day releases (YYYY.MM.DD.N).

W

Welcome Screen:
  The output shown when "buffy" is run with no arguments. Displays usage
  hints and an example command.

## Phase 0: Initialize Project

Initialize the Rust project and set up the scaffolding.

### Steps

1. Create project:
   ```bash
   cargo init --name buffy
   ```

2. Edit `Cargo.toml` with all dependencies:
   ```toml
   [package]
   name = "buffy"
   version = "0.1.0"
   edition = "2021"
   description = "Buffy CLI Automation Framework"

   [dependencies]
   clap = { version = "4", features = ["derive"] }
   serde = { version = "1", features = ["derive"] }
   serde_json = "1"
   ureq = "2"
   sha2 = "0.10"
   thiserror = "1"
   anyhow = "1"
   dirs = "5"
   colored = "2"
   chrono = "0.4"
   glob = "0.3"
   indicatif = "0.17"
   tempfile = "3"
   tracing = "0.1"
   tracing-subscriber = "0.3"

   [profile.release]
   opt-level = 2
   strip = true
   lto = true
   ```

3. Create module directory structure:
   ```
   src/

   ├── cli/

   │   ├── ast.rs
   │   ├── parser.rs
   │   ├── interpreter.rs
   │   ├── executor.rs
   │   ├── variable.rs
   │   └── error.rs
   ├── package/
   │   ├── mod.rs
   │   ├── install.rs
   │   ├── uninstall.rs
   │   ├── update.rs
   │   ├── verify.rs
   │   ├── manifest.rs
   │   └── discover.rs
   ├── repository/
   │   ├── mod.rs
   │   ├── github.rs
   │   ├── index.rs
   │   └── source.rs
   ├── config/
   │   ├── mod.rs
   │   ├── settings.rs
   │   ├── buffy_home.rs
   │   └── paths.rs
   ├── logger/
   │   ├── mod.rs
   │   └── formatter.rs
   ```

- Test that `ensure_directories()` creates all subdirectories

- Test empty state (no files exist yet)

## Phase 3: BSL Core
The heart of Buffy — parse and execute .bsl files.

### Build Order

| # | File | What to Build |
|---|------|---------------|
| 1 | `src/bsl/ast.rs` | BslScript, Metadata enum, Statement enum, WaitTarget enum |
| 2 | `src/bsl/error.rs` | BslError variants (Syntax, Runtime, UnknownInstruction) |
| 3 | `src/bsl/lexer.rs` | tokenize() — line-based, strip comments, tokens with line numbers |
| 4 | `src/bsl/parser.rs` | parse() — validate metadata section, build AST, reject unknown instructions |
| 5 | `src/bsl/variable.rs` | resolve() — ${HOME}, ${USER}, ${PWD}, ${DATE}, ${TIME}, ${TEMP}, ${1}–${N} |
| 6 | `src/bsl/executor.rs` | execute() — spawn shell, handle OUTPUT mode, capture stderr |
| 7 | `src/bsl/interpreter.rs` | interpret() — walk AST, dispatch to handlers, error on non-zero exit |
| 8 | `src/bsl/mod.rs` | Re-export public API: parse(), interpret() |

### Tests (Unit)

```bash
cargo test bsl::
```

**Lexer tests:**
- Tokenize valid script (all metadata + all statement types)
- Strip comments
- Error on empty file
- Error on malformed syntax
- Track line numbers correctly

**Parser tests:**
- Parse valid full script → correct AST
- Reject metadata after statements
- Reject duplicate metadata
- Reject unknown instructions
- Valid bool parsing for OUTPUT (true/false)

**Variable tests:**
- ${HOME} resolves to home directory
- ${1}, ${2} resolve to args
- Unknown variables left as-is or handled gracefully
- Multiple variables in one string

**Executor tests:**
- Simple command succeeds (echo)
- Non-zero exit code returns error
- OUTPUT=true shows stdout
- OUTPUT=false hides stdout

**Interpreter tests:**
- Full script executes top to bottom
- EXIT stops execution early
- WAIT pauses correctly
- Error on failed RUN stops execution

### Integration Tests

```bash
cargo test --test bsl_lexer_test
cargo test --test bsl_parser_test
cargo test --test bsl_interpreter_test
```

- Parse all fixture files, verify expected AST
- Execute fixture scripts, verify output
- Invalid fixtures produce correct errors

## Phase 4: CLI & Resolver

Wire up the command-line interface and command resolution.

### Build Order

| # | File | What to Build |
|---|------|---------------|
| 1 | `src/cli/args.rs` | CliArgs struct with clap derive (all flags) |
| 2 | `src/resolver/tree.rs` | resolve() — walk directory tree, match args to .bsl files |
| 3 | `src/resolver/mod.rs` | Re-export resolve() |
| 4 | `src/cli/dispatch.rs` | execute() — route flags to handlers, route BSL commands to resolver+interpreter |
| 5 | `src/cli/mod.rs` | Re-export args + dispatch |
| 6 | `src/lib.rs` | run() — initialize logger, ensure directories, call cli::dispatch::execute() |
| 7 | `src/main.rs` | Parse args, call buffy::run() |

### Tests

```bash
cargo test resolver::
cargo test cli::
```

**Resolver tests:**
- Resolve single arg to exact file
- Resolve multi-arg path to nested file
- Resolve to index.bsl as default
- Resolve to directory-name match
- Error on missing command
- Error on empty args

**CLI tests:**
- Parse --version flag
- Parse --install with package name
- Parse --install with GitHub URL + packages
- Trailing args for BSL commands
- No args → welcome screen

| 4 | `src/package/uninstall.rs` | uninstall() — remove files, remove from installed.json |

| 6 | `src/package/discover.rs` | discover() — scan $PATH, match tags, suggest packages, install all |
| 7 | `src/package/mod.rs` | Re-export everything |

### Tests

```bash
cargo test package::
```

**Manifest tests:**
- Validate valid package.json
- Reject missing required fields
- Auto-generate from .bsl file

**Verify tests:**
- SHA-256 matches (all 3 match)
- SHA-256 mismatch → rejection
- Exclude package.json and SHA.txt from hash

**Install tests (use mock-repository fixtures):**
- Install from local .bsl file
- Install from mock GitHub repository
- Install multiple packages
- Skip not-found packages
- Auto-generate package.json for local installs
- Install with dependency resolution
- Retry dependency once then fail

**Uninstall tests:**
- Remove package files
- Remove from installed.json
- Error on uninstall non-existent

**Update tests:**
- Update to newer version
- Remove stale files

## How to Build

### Development Workflow

```bash
# Build
cargo build

# Run (from project root)
cargo run -- --version
cargo run -- pip-env                            # Run BSL command
cargo run -- --install ./pip-env.bsl            # Install local package

# Run tests (specific module)
cargo test bsl::lexer
cargo test bsl::parser
cargo test config::
cargo test package::

# Run all tests
cargo test

# Check for warnings
cargo clippy

# Format code
cargo fmt

# Release build
cargo build --release
```

### Git Workflow

```bash
# After each phase completes
git add -A
git commit -m "Phase N: description of what was built"

# Tag releases
git tag v0.1.0
git tag v0.2.0
# etc.
```

### Testing Philosophy

- **Unit tests** live alongside code in each module (inline `#[cfg(test)] mod tests`)
- **Integration tests** live in `tests/integration/` for end-to-end flows
- **Test fixtures** live in `tests/fixtures/` — mock repos, mock buffy homes, sample scripts
- Every module should have at least 80% test coverage from day one
- Run `cargo test` before every commit

### CI Pipeline (GitHub Actions)

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions-rust-lang/setup-rust-toolchain@v1
      - run: cargo build
      - run: cargo test
      - run: cargo clippy
      - run: cargo fmt --check
```

### Release Process

1. Bump version in Cargo.toml
2. Run full test suite
3. Build release binary: `cargo build --release`
4. Test release binary: `./target/release/buffy --version`
5. Create git tag
6. Push to GitHub → CI builds and tests
7. Create GitHub Release with binary attached
